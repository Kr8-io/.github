# Support

Thank you for using Kr8.io projects! We're here to help you get the most out of our tools and resources.

## Getting Help

### Documentation

The best place to start is with the documentation in each project repository:

- Check the project's README.md for getting started guides
- Review the documentation folder (if available)
- Look through the wiki pages (if available)

### GitHub Issues

For bug reports, feature requests, and technical questions:

1. Search existing issues to see if your question has been answered
2. If not found, create a new issue with:
   - A clear and descriptive title
   - Detailed description of your question or problem
   - Steps to reproduce (for bugs)
   - Your environment details (OS, versions, etc.)
   - Relevant logs or error messages

### GitHub Discussions

For general questions, ideas, and community discussion:

- Check if the project has GitHub Discussions enabled
- Browse existing topics or start a new discussion
- Share your experiences and help others

## Common Issues

### Installation Problems

- Ensure you have the required dependencies installed
- Check that you're using a supported version of Kubernetes/tools
- Review the installation guide in the project README

### Configuration Issues

- Verify your configuration files syntax
- Check file permissions
- Review example configurations in the repository

### Performance Questions

- Review best practices in the documentation
- Check resource limits and quotas
- Monitor your cluster/application metrics

## What We Support

✅ We provide support for:
- Issues with the latest version of our projects
- Bug reports with reproduction steps
- Feature requests with clear use cases
- Documentation improvements
- Questions about usage and configuration

❌ We cannot provide support for:
- Heavily customized or modified versions
- Issues in deprecated versions
- General Kubernetes troubleshooting unrelated to our tools
- Third-party integrations not officially supported

## Response Times

We're an open-source community, and response times may vary:

- **Critical bugs**: We aim to respond within 48 hours
- **General issues**: Usually within a few days
- **Feature requests**: We review regularly and prioritize based on community needs

Please be patient and respectful. All maintainers and contributors volunteer their time.

## Commercial Support

For enterprise support, training, or consulting services, please check individual project repositories for information about commercial support options.

## Security Issues

For security vulnerabilities, please follow our [Security Policy](SECURITY.md) instead of creating public issues.
